# 04 · 公共存放区（需求级共享工作区）

## 解决什么问题

1. **物料散落**：PRD 在飞书、设计稿在 Figma、会议纪要在群里、spec 在某个 Agent 的会话里。Agent 要用时，靠人复制粘贴，或者干脆不知道有。
2. **Agent 之间传话失真**：上游 Agent 的结论靠下游 Agent 的上下文"记住"，一压缩就丢。
3. **改了不知道影响谁**：人改了 spec 的一条 AC，哪些用例、哪些代码要跟着改，没人知道。

参考了两个现实做法：
- 视频里的"物料 git 仓库"：PRD、UI 稿、spec、门禁文件、测试用例放在一个独立仓库，插件统一读写。
- 协作平台常见的"公共产物"页：按 Spec / 评审 / 外部文档 / 测试计划 / 测试报告 / 测试用例分 Tab，带版本选择和评论；需求下的所有 Agent 任务共享同一份上下文。

## 目的

**所有 Agent 和人共享同一个文件目录和信息**：需要什么就从这里取，产出什么就放回这里。存放区是需求的"单一事实源"，会话只是临时的。

## 怎么做

每个需求一个目录 `.takt/workspaces/<REQ-ID>/`，按类型分子目录：

| 子目录 | ArtifactKind | 放什么 | 谁写 |
|---|---|---|---|
| `inputs/` | input | PRD、会议纪要、设计稿、外部文档快照与链接 | 人、导入脚本 |
| `spec/` | clarification / spec | 澄清问答、spec（含 AC 编号） | PM 角色 + 人审 |
| `design/` | design / contract | 系分、接口契约、UI 契约 | 架构 / 后端 / 前端角色 |
| `test-plan/` `cases/` | test-plan / case | 测分、用例（一条用例一个文件，ID 映射 AC） | 测试设计角色 |
| `tasks/` | task | planner 拆出的开发任务 | planner |
| `evidence/<CaseID>/` | evidence | 执行证据 | 执行节点 |
| `reports/` | verdict / report | 判决、质量报告、准出报告 | judge / 报告节点 |
| `decisions/` | decision | 人工裁决、看板记录、ADR | 人、任意角色 |

**读写方式**：
- Agent 直接读写这个目录（harness 的 cwd 能访问到），不需要学新工具。
- 节点声明 `inputs` / `outputs`。引擎在节点开始前把 inputs 的清单写进上下文账本；节点结束后按 outputs 收集文件，算 sha256，写新版本（内容寻址存到 `.takt/objects/`），记录 `derivedFrom`（读了哪些输入的哪个版本）和 `producedBy`（哪次运行的哪个节点）。
- 人通过 CLI（`takt ws put / get / ls / log`）或 Web 编辑；`takt ws withdraw <path> --reason <原因> [--req <id>]` 可人工撤回（只有一个需求时可省略 `--req`），保留历史并使依赖旧版本的节点失效。人工修改必须写原因，进审计。
- 收集 outputs 时，匹配声明但磁盘已消失的登记产物追加撤回版本，记录 producedBy 和原因“产出节点重跑后文件已不存在”；当前列表、追溯和交付校验不再采用它，指定旧版本仍可读。
- 外部系统通过导入节点进来（飞书文档 → markdown 快照 + 原链接；Meego 需求 → requirement.json 的 links）。

**一致性保证**：
- `manifest.json` 记录每个产物每个版本的 sha。`detectUntracked()` 扫描磁盘，发现绕过引擎的改动就记 `artifact.untracked` 事件，Web 上标黄，让人决定"收编为新版本"还是"还原"。
- 产物改动 → 查溯源图 → 读过旧版本的节点标 `stale` → 画布标出影响面。
- 同一个产物同一时刻只有一个写者：节点的 writeScope 不能重叠，冲突在 workflow 静态校验时报错（MVP 先在运行时检测）。

## 和 git 的关系

存放区在被管理项目的 `.takt/` 下，可以随代码一起提交（推荐把 `workspaces/` 提交、`objects/` 和 `runs/` 按需提交），也可以单独放一个物料仓库（视频里的做法），通过 `takt.config.json` 指向。

## MVP 范围

- 目录约定、manifest、版本与溯源、内容寻址；CLI 的 `ws put/get/ls/log`；Web 的分类 Tab、版本切换、只读预览 + 编辑保存。
- 评论（comments.jsonl）。
- 暂不做：外部导入器（飞书 / Meego）只留接口和一个示例脚本节点。
