# 28 管家 Solo：在对话里直接看需求、节点和配置

> 状态：已确认（2026-11-09），P1 实施中（M7）。起因：很多人不想一个个空间、一个个需求点进去看状态和细节，希望像对话式助手的 Solo 首页那样，直接问管家，让它把需求的状态、节点、配置**画在会话里**。

## 结论

1. **能打通，大半已经有了。** 管家已经能跨空间读空间、需求、运行、待办、风险、配置、workflow、指标和知识库（docs/design/22）。它也能用 `show` 出可视化块，进度、风险、待办这类块由服务端用真实数据展开（docs/design/24）。`/steward` 已经是整页对话。
2. **差三件事：**
   - **实体视图**：会话里出现的是实时的需求卡、阶段泳道、运行 DAG、节点详情、路由配置，不是一张静态图。
   - **焦点面板**：在对话右侧展开完整视图，不跳页。
   - **跨空间"找"**：说"导出报表那个"就能定位到哪个空间的哪个需求。
3. **原则：模型只决定"看哪个、怎么看"，画面和数字全部来自实时接口。**
   - 新的 `entity` 块只带引用和一份当时的快照。
   - 前端用页面里同一套组件实时渲染，所以不会出现模型编出来的状态，运行在动，会话里的图也跟着动。
4. **Solo 取代现在的 `/steward` 整页**，同一个东西不做两页。各页面右侧的停靠面板保留，用来"就地问"。

## 1 页面

**首页（还没选会话）。** 从上到下是：

- 打招呼的节拍蜂和一句"想看哪个需求？"；
- 大输入框，带 `@` 引用（空间 / 需求 / 运行 / 节点）、`/` 命令，和一个范围胶囊（"全部空间 · 5"）；
- 一行短建议：等我决定的、今天有什么进展、哪些运行失败了、谁卡住了、研发用的什么模型；
- "你可能想看"：3–6 张实时需求卡，服务端按等你、失败、有风险、刚变化排序挑出来，点一下就开会话并展示。

**对话中。**

- 管家回复 = 不超过 3 句结论 + 实体视图 / 可视化块。
- 焦点面板默认跟随最新出现的实体；点 📌 固定，固定后不再跟随。
- 面板顶部是面包屑（空间 › 需求 › 运行 › 节点），可以在面板里继续点进去。↗ 在新页打开完整页面。

**窄屏（< 1100px）。** 焦点面板改成从底部升起的面板，会话保持全宽。

**地址可恢复。** 地址是 `/solo?thread=<id>&focus=run:<space>/<runId>[/<nodeId>]`，刷新或分享后回到同一视图（只有有权限的人能看到）。

## 2 实体视图（新块 `entity`）

| 视图 | 引用 | 画什么（复用的组件） |
|---|---|---|
| `card` | 需求 | 标题、状态、阶段泳道、当前节点（蜂 + 在做什么）、等你的事（带决定按钮） |
| `stages` | 需求 / 运行 | 阶段轨道 + 每阶段节点计数（`StageRail`） |
| `dag` | 运行（可带节点） | 只读 DAG 画布，在跑的边走传送带，选中节点高亮（运行页画布） |
| `node` | 节点 | 状态、harness / 模型、上下文曲线、正在做什么、最近事件、产物、门禁、改动卡（节点抽屉） |
| `attention` | 需求或空间 | 待你回答 / 审批的卡（`AttentionCard`，原因确认照旧） |
| `config` | 空间 / 角色 | 某角色或节点的路由：harness、模型、强度、备选，加近 7 天运行数、通过率、成本（`RoutingCard` 的一行 + 成绩单） |
| `diff` | 节点改动 | 改动卡：文件、diffstat，可以看 diff（`ChangeCard`） |
| `timeline` | 运行 | 时间泳道（`TimeView` 的只读版） |

另有独立的 `pick` 块：说的是哪一个？给出 2–5 个候选小卡，点一个就带着它继续问。

**协议**（`api.ts`，P1 只开放前五种视图，`config` / `diff` / `timeline` 在 P2 再加）：

```ts
| { type: 'entity'; view: 'card' | 'stages' | 'dag' | 'node' | 'attention'; ref: StewardContextRef; focus?: string; snapshot: StewardEntitySnapshot }
| { type: 'pick'; title?: string; items: StewardEntityCandidate[] }
// StewardEntitySnapshot：{ title, status, tone, summary?, stages?, at }：服务端在出块那一刻写下，离线、历史、权限变化后都能显示
```

**规则：**

- **校验与快照。** 服务端校验 `ref` 可见，不可见就降级成文字。快照由服务端从真实存储生成，模型不能写。
- **数量与挂载。** 一条消息最多 3 个 `entity` 块、1 个 `pick`。DAG、时间泳道这类重视图滚到视口才挂载；同一会话同时只保持 1 个实时 DAG，其余显示快照缩略，点开再挂。
- **"比当时"。** 历史消息里的视图默认显示实时状态，加一个小标记写明当时的状态，例如"当时在评审 → 现在已完成"。只想看当时就点开快照。
- **写操作。** 视图里的按钮（确认假设、回答、重发、回退）就是页面上那个按钮，原因确认照旧。管家自己想改东西，仍然生成提案，人批准后才执行（docs/design/22 原则 2）。
- **数据源。** Solo 是全局页，每个视图带着自己的 `spaceId` 取数（`SpaceSource` 提供者），跟随运行流 / 脉搏刷新，不靠轮询模型。

## 3 跨空间"找"

- **新工具 `find`。** 在调用者看得见的所有空间里查需求、运行、节点、workflow、知识库。
  - 排序：编号精确命中 > 标题模糊匹配 > 最近有动静。
  - 每条结果带 `spaceId`、状态、最近时间。
- **范围。** 默认全部空间，范围胶囊可以收窄到一个空间。会话里已经引用过的空间和需求优先。
- **有歧义。** 前两名分差小时，直接出 `pick` 块让人点，不猜。
- **离线可用。** 没配模型时，规则路由也能用：识别 `REQ-xxx`、`run-…`、需求标题片段，加上"进度 / 卡住 / 失败 / 配置"这些意图词，直接返回对应的实体视图。懒人最常问的"X 到哪了"不依赖模型。

## 4 盯着（给懒人的）

- 实体视图和侧栏都有"盯着它"。盯着的需求进侧栏"我盯着的"，带实时状态点。
- 状态有变化时，往发起盯着的那个会话里追加一张系统更新卡，例如"REQ-002：失败判决 → 打回研发（代码缺陷），第 3 轮开始"。这张卡不调用模型，并沿用脉搏的系统通知。
- 每天的汇报（digest）先讲盯着的需求。

## 5 评测与度量

- **eval:steward 加场景：**
  - 找对实体，包括同名、跨空间、编号写错一位；
  - 问进度时出实体视图而不是文字表格；
  - 回答里的数字都能在工具输出里找到；
  - 离线路由命中。
- **效率指标（docs/design/22 原则 4）：**
  - 问"X 到哪了"到看见视图的时间；
  - 会话里直接完成的决定（确认假设、回答）占全部决定的比例；
  - 从 Solo 跳去完整页面的比例（越低说明视图够用）。

## 6 范围与顺序

**P1：能问能看。**

- `/solo` 外壳：合并 `/steward`，原地址跳转；侧栏"我盯着的"和最近会话；首页加输入框和"你可能想看"。
- `entity` 协议、快照、`find` 工具、离线路由。
- 视图：`card`、`stages`、`dag`、`node`、`attention`，加 `pick` 块；首页"你可能想看"（`/api/steward/picks`）。
- 焦点面板（跟随 / 固定、面包屑、窄屏底部面板）。

**P2：更省事。**

- 视图：`config`、`diff`、`timeline`。
- 盯着和系统更新卡。
- "比当时"标记。
- digest 合并盯着的需求。
- 评测场景与指标面板。

**分工照旧：** 协议和前端由 Claude 做；`find`、快照、规则路由、盯着的后端由 Codex 做，简报写在 `docs/dev/m7-backend.md`。

## 7 不做

- 模型生成任意界面代码：只从这套领域组件里选，组件树由服务端校验。
- 在对话里不经确认直接执行写操作。
- 把 Solo 做成第二套总览：跨空间的汇总仍以实体卡为单位，不另做一张大看板。
