# 27 形象、动效与运行时接入

> 状态：M6。参考：ACP 规范（agentclientprotocol.com，2026 版：`usage_update`、`compaction_update`、`session/resume` 已稳定）；常见 agent 产品的吉祥物做法（一个有性格的形象，按状态换表情、按在干的活拿道具、关键时刻做一次性小动作）。形象原创，不借用任何现有吉祥物的造型与配色。

## 结论

1. **taktflow 有一个原创吉祥物，同时是每个 Agent 在界面上的化身。** 品牌标、空态、加载、Agent 节点、管家头像用同一个形象；按状态换表情，按角色拿道具，循环动作对齐节拍（`--takt`）。候选三选一（§1），选定前不换 logo。
2. **DAG 的边能看见"东西在流"。** 首次出现时信号沿拓扑顺序把边点亮；运行中通往在跑节点的边走传送带；节点完成时一颗信号沿出边送到下游；打回反向流；悬停只让相关路径流动。已结束的运行默认静止，可以"回放"。
3. **Harness 加 ACP 适配器。** 一个适配器接所有支持 ACP 的 agent（50 多个，含 Gemini CLI、Claude Agent / Codex 的 ACP 适配、OpenCode、Qwen Code、Kimi CLI、Goose、Copilot），配一条启动命令即可；现有逐个 CLI 的适配器保留。
4. **模型与 Harness 在设置页可改。** provider、模型别名、角色路由、系统角色、自加的 harness、内置 harness 的命令路径都能在界面上改，改完不用重启；能测试连通；密钥只存环境变量或本机密钥库，任何接口都不回传。
5. **回执会自动过期；重发进运行记录。** 派出的任务超时没人接手标"过期"，服务重启后找不到下落的标"不确定"；重发在原 Lead 运行里记一条派发事件。

## 1 吉祥物：节拍蜂

**定稿**：三个候选里选了 A 节拍蜂（圆身子、两道条纹、小翅膀、两根触角；翅膀按节拍扇动就是"takt"）。B 小水獭、C 节拍器精灵不再做。

**用在哪**：侧栏品牌标与底部字标、favicon（带运行中 / 等你的状态点）；大号空状态（睡着）与出错（失败 / 没权限时求助）；运行页 Agent 节点（替换 docs/design/25 的 AgentMark 脸，身体按 harness 着色）；管家头像与停靠面板欢迎页。

**状态与小动作**：8 个状态，每个状态 = 默认表情 + 一拍一拍的基础循环 + 一池小动作（共 60 个，另有 6 种互动反应）。

| 状态 | 用在 | 小动作 |
|---|---|---|
| 待命 | 节点排队、品牌标 | 左右张望、天线抖一抖、打哈欠、伸翅膀、原地小跳、哼小曲、绕小圈、歪头看你、挠头 |
| 打招呼 | 首次打开、欢迎页 | 挥手、眨眼、鞠躬、冒爱心、蹦一下、转圈 |
| 干活 | 节点在跑 | 手里工具在 读文件 / 搜索 / 改代码 / 跑测试 / 派任务 之间换，每种工具有专属动作；盯紧、擦汗、天线一亮、跟拍点头 |
| 思考 | 规划、管家回复中 | 拍拍脑袋、眼珠乱转、歪头琢磨、天线转圈、嗯……、灵光一闪 |
| 求助 | 等人审批 / 回答 | 举手、跳着催、探头看你、扑翅膀、眼巴巴、天线竖起 |
| 完成 | 节点通过 | 蹦一下、空翻、连蹦两下、比耶、撒花、扑翅欢呼、扭一扭 |
| 失败 | 节点失败、加载出错 | 叹气、摇头、眼冒金星、抹眼泪、打起精神又蔫回去、天线耷拉 |
| 睡着 | 空状态 | 吹鼻涕泡、说梦话、天线抽一下、翻身、眯眼偷看、打瞌睡点头 |

- **挑法**：默认洗牌轮换（一轮里每个动作都会轮到、权重高的多几次、不连着重复）；间隔 0.8–5 秒随状态不同；眨眼单独随机（2–5.6 秒，两成概率连眨两下）；进入状态先播入场动作（完成蹦一下、失败叹气、求助举手、打招呼挥手）。
- **互动**：点它咯咯笑 / 吓一跳 / 被捏扁，2.6 秒内连点四下"别戳啦"，睡着时点它会被戳醒；指针移入时注意到你。
- **克制**：品牌标只用 5 个轻量动作且间隔加倍；DAG 里只有在跑 / 等人的节点挑小动作，其它节点安静，只在切状态时播入场动作；管家历史消息头像静止，只有正在回复的那条会动；≤ 24px 只画轮廓、条纹和眼睛，头顶符号用角标补。
- **角色道具**：architect 尺子、dev 扳手、reviewer 放大镜、test 试管、judge 小锤、pm 便签、lead 指挥棒、steward 小铃铛、派任务的信封。
- **省电与无障碍**：标签页在后台、蜂不在视口里时不挑新动作；reduced-motion 下所有循环与一次性动作都不播，只保留每个状态的静态表情。
- **实现**：`packages/web/src/components/mascot/`（`Bee` 组件；SVG 只渲染一次，`BeeEngine` 只改根节点 data-* 与部件的 animation，不触发重渲染）。只用 SVG + CSS，不引 Lottie / 3D；原创形象，不做章鱼 / 团子 / 渐变光球这类已有产品在用的形象。

## 2 动效

### 2.1 DAG 的边

| 场景 | 表现 |
|---|---|
| 首次出现 | 按拓扑层从入口到出口描线（`stroke-dashoffset`），层间隔 60ms，总时长 ≤ 1.2s；描到的节点外环亮一下 |
| 运行中 | 通往在跑节点的边走传送带虚线（上游 → 下游），每拍前进一格；在跑节点外环随拍呼吸 |
| 节点完成 | 一颗信号点（吉祥物选 A 时是一只小蜂）沿每条出边送到下游，约 600ms；下游开始时外环亮一下 |
| 打回 | 紫色虚线**反向**流动，标签"打回 ×N"在流到时轻跳 |
| 判决路由 | 橙色，只流向被选中的修复节点 |
| 悬停 / 选中节点 | 上游与下游路径高亮并流动，其余边与节点降到 35% |
| 已结束的运行 | 默认静止；工具栏"回放"把整次运行按真实先后压到 6 秒重演（节点亮起、信号沿边走），可中途停 |
| Workflow 编辑器 | 选中节点时它的边流动；新加的边描线出现；预览中的增删边（docs/design/24 幽灵编辑）虚线流动 |

- 只用 SVG 描边属性与 `offset-path`，不重排布局；同屏流动的边 ≤ 24 条，超过时只保留悬停路径与在跑节点的入边。
- 标签页隐藏（`data-tab-hidden`）暂停；reduced-motion 下全部静止，在跑的边用实色加粗代替流动。

### 2.2 全站巡检

逐页过一遍"入场、悬停、状态变化、加载、空态"五类时刻，每类一个规范（写进 DESIGN.md 的动效表）：入场分层（已有）；悬停给可点的东西轻抬与指示；状态变化只做过渡不重播；加载用吉祥物待命 + 骨架；空态用吉祥物 + 一句下一步。数字读数变化时滚动到新值。motion-audit 的时长与缓动约束照旧。

## 3 ACP 适配器

**为什么**：ACP 是编辑器 ↔ agent 的开放协议（stdio 上的 JSON-RPC 2.0），已经被 50 多个 agent 支持。我们现在每接一个 CLI 都要写一个解析器；ACP 一个适配器就能接住它们，并且有结构化的工具调用两拍、计划、用量与压缩事件，正好对上我们的账本与时间视图。逐个 CLI 的适配器保留（已有测试，部分能报成本）；新 agent 默认走 ACP。

**配置**：`TaktConfig.harnesses` 里写 `{ id, kind: 'acp', preset? , command?, env?, permissions? }`（`AcpHarnessConfig`）。内置预设给出常见 agent 的启动命令与安装说明（`GET /api/space/runtime` 的 `presets.acp`）。

**映射**：

| ACP | takt |
|---|---|
| `initialize`（clientCapabilities：`fs.readTextFile / writeTextFile` 为 true，terminal 为 false） | 记 agent 名称、版本与能力，换算成 `HarnessCapabilities`（resume、toolPhases、usage、compactionEvents、mcp、modelOverride 按 agent 声明） |
| `session/new`（cwd = 节点工作目录；mcpServers = 知识层可挂载时的 MCP） | `harness.started`（sessionId、contextWindow） |
| `session/prompt` → `stopReason` | `end_turn` 成功；`max_tokens / max_turn_requests / refusal` 失败并写原因；`cancelled` 为取消 |
| `agent_message_chunk` / `agent_thought_chunk` | `harness.message`（思考单独标记） |
| `tool_call` / `tool_call_update` | `harness.tool_call`，`phase: start / end`、`callId`、`durationMs`；`kind`（read / edit / execute / search / fetch …）对应 docs/design/25 的动词 |
| `plan` | 节点的计划条目（时间视图与抽屉显示） |
| `usage_update` | 用量与上下文窗口（账本、上下文曲线） |
| `compaction_update` | `context.compacted` |
| `session/request_permission` | 按 `permissions`：目标在工作目录内放行一次，否则拒绝；只读运行时写类一律拒绝；每次都记事件 |
| `fs/read_text_file` / `fs/write_text_file` | 只允许工作目录与公共存放区内的路径；只读运行拒绝写 |
| 续会话 | agent 声明 `loadSession` / `session/resume` 时支持 resume，否则不支持（如实标注） |
| 选模型 / effort | agent 通过会话配置项（config options）暴露时设置并记 `applied: true`；否则 `applied: false`，不拿请求值冒充实际值 |
| 取消 | `session/cancel`，等 prompt 返回 `cancelled`，超时再结束进程 |

**不做**：client 侧终端（`terminal/*`，agent 用自己的工具跑命令）；HTTP / WebSocket 远程传输（推后）。

## 4 模型与 Harness 配置

**能改什么**（都在 takt.config.json，设置页只改这几段）：

- **Provider**：选预设（自动填 baseURL、协议、建议的环境变量名）或自定义；密钥选"环境变量"或"存到本机密钥库"。
- **模型别名**：provider + 厂商模型 ID + 类型（对话 / 向量）+ 上下文窗口 + 价格。
- **角色路由**：角色 → harness + 模型 + effort + 备选（fallback）。
- **系统角色**：Lead、路由判档、管家、经验提炼各用什么。
- **Harness**：内置的可以设可执行文件路径、加环境变量、在本空间停用；可以加 ACP agent（选预设或填命令）与声明式 CLI，自加的可编辑删除。
- **测试**：provider 只列模型（不计费）；模型测试要勾"允许一次最小计费请求"；harness 跑可用性探测，ACP 做一次 `initialize` 握手并显示 agent 名称、版本、能力。

**写入**：`PATCH /api/space/runtime`（`RuntimeConfigPatch`）按段打补丁，带 `baseRevision` 与原因；校验失败 400 并指出字段（例如"模型 x 指向不存在的 provider y"、"角色 dev 用的 harness gemini-cli 已停用"）；写盘原子、进空间审计；serve 不重启即生效（重建 harness 注册表与模型解析，正在跑的节点不受影响）。

**密钥**：环境变量优先；"本机密钥库"是 `~/.config/takt/secrets.json`（权限 0600，按机器，不进空间目录与 git）。任何接口、日志、事件、审计都不出现密钥值；界面只显示来源（环境变量 / 本机 / 缺失）。

## 5 回执过期与重发记账

- serve 定时（与等人时限同一节拍）把超过 `lead.receiptTimeoutMinutes`（默认 30）仍是"已发出"的任务标为过期：追加一条同 taskRunId 的 task 消息（`receipt.status: 'expired'`），不改原消息。
- serve 启动时，回执还停在"已发出 / 已接手"、却找不到对应运行状态（或运行已不在本进程里且没有结束）的任务，标为"不确定"，写明"服务重启，可能已送达，重发前先看群聊"。
- 管家转达已有同类逻辑，两边口径一致（同一个超时配置的缺省值）。
- 重发：在原任务的父运行（Lead 运行）里追加 `task.dispatched`，带 `resendOf`（原任务运行 id）与 `reason`；运行页时间线显示"重发任务「…」"。

## 6 不做 / 推后

- 吉祥物的 3D、Lottie、可换装；按用户自定义形象。
- ACP 的远程传输、client 侧终端、agent 自带的斜杠命令。
- 密钥的团队共享（多人空间各自配本机密钥或环境变量）。
- ACP 的结构化事件：思考、计划、上下文用量（`usage_update` 的 used / size / cost）、压缩（`compaction_update` 按 ID 合并）、每次调用的模型 / effort 是否生效，目前都以 `[ACP …]` 系统消息留在运行记录里，不进账本、时间视图与上下文曲线；需要协议加对应事件（适配器交付说明 `packages/harness/src/acp/README.md` 的 5 项协议变更请求，含 `HarnessRequest.mcpServers`）。在此之前 ACP harness 的 usage / cost / compactionEvents 能力如实标为不支持。
