# 22 · 管家 Agent 与操作体验

## 解决什么问题

M0–M3 的页面主要是**看板**：能看进度、产物、评审、评测，但很多事做不了，做得了的也很费劲。

| 现象 | 根因 |
|---|---|
| 页面上没法新建需求、新建或删除空间；知识源、模型、角色多数要改 `takt.config.json` | 写操作只做了一部分，空状态还在教人改文件、跑 CLI |
| 要逐个点进需求才知道进度和风险 | 信息全靠人拉，没有人主动汇报 |
| workflow、知识库、模型路由，很多人不知道怎么配 | 只有 Lead Agent，而且它只管一个需求；页面上没有一个能"替我做"的 Agent |
| workflow 文件不是 `defineWorkflow({...})` 写法时，编辑器只给一句报错 | 解析失败后没有下一步 |
| 空间切换器弹层压住页面，两个空间同名分不清 | 弹层没走浮层原语；名称没做唯一约束 |
| 用起来"粗糙"：没有转场、加载靠省略号、数字直接跳变 | M3 的动效规范只约束了"不许怎样"，没规定"每个页面必须有什么" |
| 功能上线后不知道好不好用 | 没有给每个功能定义效率指标和迭代信号 |

## 原则

1. **页面能做的 = 命令能做的 = 管家能做的**。所有写操作只有一个实现，就是命令注册表（`/api/commands`）。页面按钮、⌘K、CLI、Lead、管家都调用它。新功能必须先注册命令，再做界面。
2. **管家提案，人把关**。管家的写操作一律先生成**变更提案**：一份可预览的改动，人批准后才执行。提案可以撤销，全程审计。
3. **不让用户去改文件**。页面不能把"编辑某文件"或"运行某 CLI"当作唯一路径。源文件编辑只作为高级入口保留。
4. **每个功能自带度量**。上线时同时定义它的效率指标和迭代信号（见第 5 节），有数据才知道往哪改。

## 1. 管家

### 1.1 定位

| | Lead Agent（[15](15-需求群聊与Lead-Agent.md)） | 管家 |
|---|---|---|
| 范围 | 一个需求 | 一个用户能看到的所有空间 |
| 在哪 | 需求群聊 | 侧栏入口、整页对话，以及任意页右侧的停靠面板 |
| 做什么 | 推进流水线、派临时任务 | 回答问题、主动汇报进度与风险、替用户配置和操作 |
| 怎么写 | 动作 JSON，经命令注册表执行 | 变更提案，人批准后经命令注册表执行 |

需求内部的事，管家不自己动手，而是**转达给 Lead**：它以 `steward` 身份在需求群里发一条带引用的消息，由 Lead 执行，结果回到管家会话里的同一张卡片上。这样需求内的所有动作仍只有一条留痕链。

### 1.2 入口

- **侧栏顶部的管家按钮**（⌘J），打开整页 `/steward`：左边是会话列表与"动态"，右边是对话。
- **右侧停靠面板**：在任意页按 ⌘J 或点页头的管家图标打开。面板会自动带上当前页的上下文，以标签形式显示，可以删掉：
  - 空间、需求、运行；
  - workflow 及选中的节点；
  - 知识库。
- **页内建议**：空状态和页头放 1–3 条"让管家……"的建议，内容由当前页决定。例如：
  - 知识库页：从 `docs/` 建一个文档知识库；
  - workflow 页：在测试之后加一个交叉评审；
  - 模型页：把评审节点都换成另一家模型。
- **⌘K 兜底**：输入的内容匹配不到命令时，最后一项是"问管家：……"。

### 1.3 对话

- 会话可持久保存、可按标题搜索。
- 输入框：
  - `@` 引用空间、需求、运行、workflow、节点、知识库或文件；
  - `/` 选择命令注册表里的命令；
  - 可以拖入附件。
- 一条管家回复依次包含：
  1. 思考摘要（默认折叠）；
  2. 工具调用卡：查了什么、耗时、返回几条，可展开看原始结果；
  3. 正文：涉及进度、数字、状态的每一句都要带来源链接。点击链接跳到对应的需求、运行或事件，并高亮定位；
  4. 提案卡（如果有写操作）；
  5. 最多 3 条后续建议。
- **数字只能来自工具结果**，不允许凭模型记忆回答。没有工具结果支撑的句子不带链接，评测时按"无引用"计数（见 1.8）。
- 每条回复有复制、👍、👎 按钮；点 👎 时可选原因：答错、没答到点、太啰嗦、操作不对。

### 1.4 能力

管家的工具就是命令注册表加几类只读查询，不另建一套。

| 类别 | 工具 | 执行方式 |
|---|---|---|
| 查询 | 空间 / 需求 / 运行 / 待办 / 度量 / 预算 / 风险 / workflow 与 lint / 知识检索 / 配置 / 成绩单 / 空间内文件读取 | 直接执行 |
| 写 | 注册表里所有 `write` / `dangerous` 命令，以及本篇新增的需求、空间、配置、workflow、知识库命令 | 先生成提案，人批准后执行 |
| 转达 | `lead.ask(requirementId, message)` | 发到需求群，异步回填 |

- **harness 与模型**：在管家设置里选。默认用 native harness，通过函数调用使用上面的工具。claude、codex 这类外部 harness 通过 `takt` CLI 使用同一套工具（以后再接 MCP）。
- **未配置模型时的降级**（demo、测试、离线环境）：用确定性规则识别几类意图：
  - 能直接回答：进度、风险、待办；
  - 能出提案：新建需求、新建空间。
  - 其余意图回复"需要先配置管家模型"，并附上设置入口。

### 1.5 变更提案

```ts
interface Proposal {
  id: string
  threadId: string
  title: string                 // 一句话："在 test 之后加交叉评审节点"
  summary: string               // 为什么改、影响什么
  risk: 'low' | 'medium' | 'high'
  steps: ProposalStep[]
  hash: string                  // steps 规范化后的 sha256，批准绑定它
  status: 'pending' | 'applied' | 'rejected' | 'failed' | 'reverted' | 'stale'
  createdBy: Actor              // { type: 'agent', id: 'steward' }
  decidedBy?: Actor; decidedAt?: Timestamp
  edited?: boolean              // 人在批准前改过内容
  undo?: ProposalStep[]         // 执行成功后生成
}
type ProposalStep =
  | { kind: 'command'; commandId: string; input: Record<string, unknown> }
  | { kind: 'workflow'; workflowId: string; baseRev: string; edits: WorkflowEdit[] }
  | { kind: 'file'; path: string; baseHash?: string; content: string }   // 只限空间内文件
```

- **预览**：每种步骤都有自己的预览形式。
  - 命令：参数表单（可直接改）；
  - workflow：画布上的幽灵覆盖层（新增节点绿色虚线、删除节点红色划线、改动节点琥珀色角标）加属性差异；
  - 文件：统一 diff。
- **批准**：批准绑定提案的 `hash`。批准时如果基线已经变了（`baseRev` / `baseHash` 不一致），提案状态变为 `stale`，需要管家重新生成。
- **执行**：按顺序逐步走命令注册表。
  - 执行者是批准人，记录 `onBehalfOf: steward`，原因是"提案标题 + 会话链接"。
  - 某一步失败就停下，自动撤销已经成功的步骤，再报告失败。
- **撤销**：在执行后 24 小时内、且目标没有被其他人改过时可用。
  - workflow：回滚到批准前的修订；
  - 配置：恢复到上一个配置修订；
  - 新建需求或空间：改为归档。
- **信任档位**（用户偏好）：
  - **每次确认**：默认档位。
  - **低风险自动执行**：只对 `low` 且可撤销的步骤生效，例如新建草稿需求、新建知识库草稿、写管家记忆。自动执行后在对话里显示"已执行，可撤销"。
  - `high` 永远需要确认，例如删除、取消运行、修改正在运行的 workflow、写数据库凭据。删除类操作还要手动输入名称确认。

### 1.6 主动汇报

**风险**由确定性规则产生（`insights/risks.ts`），不交给模型判断：

| key 前缀 | 条件 | 级别 |
|---|---|---|
| `waiting-human` | 待办超过 4 小时 / 超过 24 小时 | 中 / 高 |
| `budget` | 用量达到 80% / 100% | 中 / 高 |
| `stalled` | 运行中，但 15 分钟没有新事件 | 高 |
| `repeat-failure` | 出现失败指纹抑制 | 高 |
| `review-stuck` | 评审因 `no_progress` 早停，或轮次用完 | 中 |
| `gate-failed` | 交付校验未通过 | 高 |
| `deadline` | 设置了 `dueAt`，剩余时间少于 25%，且还有阶段未完成 | 中 |
| `defect-escape` | 有已确认的逃逸缺陷 | 中 |
| `regression` | 成绩单显示疑似退化 | 中 |
| `knowledge` | 知识库构建失败、过期，或召回率下降（[23](23-知识库体系.md)） | 中 |

- **每条风险的结构**：
  - key 格式为 `<前缀>:<space>/<req>/<对象>`，用来去重；
  - 级别；
  - 证据链接；
  - 首次与最近出现时间；
  - 建议动作，点击后直接生成对应提案。
- **汇报内容**：
  - 定时汇报：默认工作日 09:30 和 18:00，可以改。
  - "自上次以来"横幅：打开页面时，如果有新变化就显示。
  - 汇报顺序：需要你处理 → 新风险 → 进展（阶段推进、已交付）→ 指标变化。
  - 列表全部由规则生成，模型只写开头两句摘要。
- **送达渠道**：
  - 管家页的"动态"；
  - 浏览器通知（需要用户主动开启）；
  - IM webhook 走插件，本期只定接口。
- **控噪**：
  - 同一个 key 只提醒一次；只有级别升高，或 24 小时后仍未解决，才再次提醒；
  - 支持对单条风险"稍后提醒"或"忽略"，也支持按空间静音和设置免打扰时段；
  - 如果某类风险两周内"提醒 → 处理"的比例低于 10%，管家会提议调整它的阈值。

### 1.7 记忆与偏好

- **偏好**：
  - 关注的空间；
  - 汇报时间；
  - 信任档位；
  - 默认空间（未指定时，新建需求建在这里）；
  - 管家的 harness 和模型。
- **记忆**：`profile.md` 由人和管家共同编辑。管家想记住一件事时，会提一个 `low` 风险的提案，比如"记住：我主要关注 standard-delivery"。
- **存储位置**：`<spaces 根>/.steward/<userId>/`，内含：
  - `threads/*.jsonl`
  - `proposals/*.json`
  - `risks.json`
  - `prefs.json`
  - `profile.md`
  - `metrics.jsonl`
- 用户身份沿用 `/api/me`。

### 1.8 评测与迭代

- **评测用例**：放在 `evals/steward/*.json`，每条包含问题、上下文、期望。期望可以是三类之一：
  - 应调用的工具；
  - 回答必须包含的事实；
  - 应生成的提案（命令 id + 关键参数）。
- **执行**：复用 [20](20-评测与归因.md) 的回放评测，目标类型为 `steward`。
- **线上指标**：
  - 引用覆盖率：带来源链接的事实句占比；
  - 提案通过率、改后通过率、拒绝率（附拒绝原因）；
  - 执行失败率、撤销率；
  - 首字延迟；
  - 👍/👎 率；
  - 汇报的点击率。
- **管家周报**：每周把"被拒最多的提案类型"和"👎 最多的问题"整理出来，生成经验或评测用例，进入 [19](19-外部参考与改进.md) 的经验库流程。

## 2. 需求与空间的增删改

### 2.1 新建需求

**入口**（都打开同一个对话框）：

- 侧栏"需求"右侧的 `+`；
- 需求页的主按钮；
- 总览空状态；
- 快捷键 `C`；
- ⌘K 的 `requirement.create`；
- 对管家说"帮我建个需求……"。

**对话框**：

- **主体**：一个大文本框，用来写背景、目标和验收标准。可以粘贴 PRD，也可以拖入文件。
- **标题**：默认取首行，可以改。
- **下方一排标签**：
  - **流程**：默认"自动"。输入停顿 600ms 后调用路由预览，实时显示档位图形、workflow 名和一句理由；点开可以手动指定。
  - **仓库**、**负责人与成员**、**预算**、**截止时间**、**关联链接**。
- **开关**：创建后立即启动，默认打开。
- **"让管家补全验收标准"**：管家逐条给出验收标准，插入到文本框里，每条可以单独接受或拒绝。
- **提交后**：
  - 描述写入 `inputs/prd.md`，附件放进 `inputs/`。这样流水线不会再因"缺少必需输入"失败。
  - 草稿按空间存在浏览器本地，⌘Enter 提交。
  - 提交后弹出提示，带"撤销"按钮（撤销即归档）；页面跳到需求群聊，Lead 发出第一条消息。

**编辑与删除**：

- 需求页头部的标题、描述、负责人、截止时间、链接都可以直接改。
- 需求可以归档和恢复。
- 只有没有任何运行记录的需求可以删除，否则只能归档。

### 2.2 空间

**新建**：一个三步对话框。

1. **名称、ID、描述、颜色**：ID 从名称自动生成。ID 必须唯一；名称和已有空间重复时，提示并要求修改。
2. **起点**：四选一。
   - 空白；
   - 标准交付流水线；
   - 快速修复；
   - 复制已有空间：勾选要复制的部分，包括角色、技能、workflow、知识库绑定、模型设置。
3. **仓库与成员**：可以跳过。仓库填本地路径或 git URL 加默认分支；创建者自动成为 owner。

完成后进入新空间的总览。空状态给出两个入口："新建第一个需求"和"让管家帮我配置"。

**管理**（`/spaces`）：

- 所有空间以卡片网格展示：需求数、进行中数、风险数、最近活动。
- 支持重命名、改描述、改颜色。
- **归档**：把空间移到 `<根>/.archive/<id>@<时间>/`，可以恢复。有运行中的需求时拒绝归档。
- **彻底删除**：只能对已归档的空间操作，并且要手动输入 ID 确认。
- 只在服务以 `--spaces` 多空间模式启动时才能新建空间。单空间模式下，新建按钮会说明原因，并给出用当前目录的上级目录启动多空间模式的方法。

**切换器修复**：

- 弹层改用浮层原语（portal），对齐在触发器下方，宽度不小于 280px，最大高度 60vh，超出可滚动。
- 超过 5 个空间时显示搜索框。
- 名称重复时，在名称下方显示 ID。
- 弹层底部放"新建空间"和"管理全部空间"，删掉原来的 CLI 提示。

### 2.3 workflow 编辑的兜底

- 源文件不是 `defineWorkflow({...})` 写法时，编辑器顶部显示原因，并给出"转换为可编辑格式"。
  - 能确定性改写的就直接改写，例如 `export default {...}` → `export default defineWorkflow({...})` 并补上 import。
  - 改写不了的，交给管家出一份文件提案。
  - 画布照常用运行时加载出来的定义渲染，只是只读。
- 修复示例里的 `chat-auto.workflow.ts`。
- **编辑器里的"问管家"**：上下文自动带上 workflow 和选中节点。
  - 管家返回 workflow 提案，画布上用幽灵覆盖层预览。
  - 接受后带着 `baseRev` 保存；如果冲突，由管家基于新版本重新生成。

## 3. 体验与动效

M3 的动效规范（`docs/dev/m3-web.md`、`DESIGN.md`）规定了数值上限和禁用写法。本篇补上"每个页面必须有什么"。

### 3.1 必备状态

每个异步区域都必须有下面四种状态，并在评审时逐页检查：

- **加载**：骨架屏加扫光。只有加载超过 120ms 才显示，避免一闪而过；不再用"…"表示加载中。
- **空**：一句话说明，一个主动作，再加一个"让管家帮我"。
- **错误**：说明原因，提供重试；如果是权限问题，告诉用户去找谁。
- **成功反馈**：提示条，能撤销的都带撤销。提示条从底部居中升起，5 秒后消失，最多堆叠 3 条。

### 3.2 转场与动效

| 场景 | 规格 |
|---|---|
| 路由切换 | 旧页淡出 120ms，新页淡入并上移 6px，200ms，`cubic-bezier(.2,.8,.2,1)`。浏览器支持时用 View Transitions，需求标题从列表到详情做共享元素过渡 |
| Tab 切换 | 下划线指示器平移（transform），内容交叉淡化 150ms |
| 列表首屏 | 逐项入场，每项间隔 24ms，最多 10 项，单项 160ms；之后的数据更新不再做入场动画，新行底色闪一下（1.2s 淡出） |
| 数值变化 | 从旧值过渡到新值，400ms，等宽数字；首屏只用于总览统计 |
| 按压 | 按钮 `scale(.98)`，80ms；焦点环淡入 |
| 实时状态 | 运行中节点：按 `--takt` 节拍呼吸的外环。流式文本：光标闪烁。"思考中"：文字扫光。工具卡展开：`grid-template-rows: 0fr → 1fr`，不对 height 做过渡 |
| 管家面板 | 从右侧滑入：`translateX(16px)` 加淡入，220ms。消息淡入并上移 160ms。提案执行成功后对勾描边 300ms，同时让页面上对应的元素高亮定位 |
| 弹层 / 对话框 | 沿用 M3 数值，所有弹层都走 `components/ui` 原语，保证有退出动画、焦点管理和 Esc 关闭 |

所有动效都要遵守 `prefers-reduced-motion`：开启后去掉位移和缩放，只保留透明度变化。

### 3.3 视觉

- **三层表面**：页面底色、卡片、浮层。浅色主题用细阴影区分，深色主题用亮度和描边区分。少套框，多用间距和色调来分组。
- **强调色只用在两处**：主动作和实时状态。
- **尺寸刻度**：
  - 间距：8px 网格；
  - 圆角：6 / 10 / 14；
  - 字号：12 / 13 / 14 / 16 / 20 / 28。
- **统一页头**：标题、一句说明、主动作、管家建议。
- **空状态插图**：单色线稿，风格与档位图形一致。

### 3.4 体验门禁

  - 页面文案里出现 `takt.config.json`，或 "运行 `takt …`" 这类指引，并且附近没有对应按钮时，报警告；
  - 用"…"表示加载中，报违规；
  - 异步区域没有空状态，报违规。

### 3.5 性能预算

- 交互响应 < 100ms；

## 5. 每个功能的度量

指标只记录在本机的 `.steward/<user>/metrics.jsonl` 和空间事件里，不对外发送。管理员可以在管家页的"产品健康"里查看。

| 功能 | 效率指标 | 迭代信号 | 用来改什么 |
|---|---|---|---|
| 新建需求 | 从打开对话框到提交的用时；创建后 5 分钟内启动的比例 | 路由被手动改的比例；"补全验收标准"被采纳的比例 | 路由规则、验收标准提示词 |
| 管家问答 | 首字延迟；平均工具调用数 | 👎 率及原因；引用覆盖率；工具报错率 | 工具设计、提示词、评测用例 |
| 管家提案 | 从提出到决定的用时 | 通过、改后通过、拒绝、撤销的比例，按命令分类统计 | 提案模板；信任档位的默认值 |
| 主动汇报 | 风险从出现到处理的用时 | 每类风险"提醒 → 处理"的比例；稍后提醒和忽略的比例 | 阈值、汇报时间 |
| workflow 编辑 | 一次改动的用时 | 保存后出现 lint 错误的比例；提案冲突率 | 编辑器交互、codemod |
| 空间 | 新建空间到出现第一个需求的用时 | 各起点模板的选择比例 | 模板内容 |
| 知识库 | 见 [23](23-知识库体系.md) | 召回率、引用率 | 切块、检索参数、补文档 |

## 不做什么

- 不在本期接 IM 推送和语音输入，只定插件接口。
- 管家不绕过命令注册表直接写文件。即使是"文件提案"，也通过 `space.files` 这类带审计的写入口落盘。
- 不做多租户鉴权；身份沿用 `x-takt-user`。

## MVP

1. **管家**：
   - 整页和停靠面板；会话；只读工具；
   - 提案覆盖：新建需求、新建空间、workflow 编辑、配置修改（成员、仓库、模型、角色）、知识库新建与绑定；
   - 风险引擎和站内汇报；偏好与记忆；
   - 未配置模型时的确定性降级。
2. **增删改**：需求的新建、编辑、归档；空间的新建、归档、恢复、从归档中彻底删除；切换器修复。
3. **workflow**：编辑兜底和 codemod；示例修复；编辑器内的"问管家"与画布预览。
4. **体验**：转场、骨架屏、数值过渡、空状态、提示条、统一页头；`DESIGN.md` 更新；`ux:audit`。
