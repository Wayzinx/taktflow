# 26 运行透明与回退

> 状态：M5（与 docs/design/21 同一批）。参考：Agent HUD（细分状态、子 Agent 甘特、上下文窗口曲线、等人限时交还、互发消息的回执与跳数上限）、MeowCode（回合改动卡、检查点回退预览）。只借思路，不拷代码与图形。
> 名词区分：docs/design/21 的"检查点"是**评审 / 门禁的一次判断**；本文的"回退点"是**节点开始前的文件状态**，两者不混用。

## 结论

1. **运行中说清在干什么。** 运行中的节点不只是"运行中"：思考、读、搜、改、跑命令、访问、派给、压缩上下文、等工具，一步超过 15 秒标"长步骤"。数据来自 harness 事件，工具调用分开始 / 结束两拍。
2. **一次运行能按时间看。** 运行页加"时间"视图：每个节点一条泳道（Agent 节点再细到每次调用、每个工具步骤），可拖拽缩放；下面是上下文窗口曲线（每轮输入 token，标出窗口上限与压缩点）。
3. **等人有时限，从不替人拍板。** 等人的事项可以设时限：到点先提醒（再提醒负责人）；只有"回答问题"且提问方给了默认假设时，才按假设交还给 Agent 继续，并留一条"按假设推进，待确认"的待办。审批与选择永远不会自动通过。
4. **转达有回执，派活有跳数上限。** 管家转达 Lead、Lead 派发任务都有状态：已发出 / 已接手 / 已开始 / 完成 / 已回复 / 拒绝 / 过期 / 不确定；不盲目重发。任务派任务的链有跳数上限（默认 10），超过就拒绝并说明。
5. **每个节点改了什么一眼可见，能退回去。** 节点结束时出一张改动卡（文件、+A −D、看 diff）；"退回到这个节点之前"先出预览（会恢复哪些文件、哪些下游会过期），确认后才执行，并进审计。

## 1 运行中细分

| 状态 | 判定（同一节点最近的 harness 事件） |
|---|---|
| 思考 | 最近是 assistant 消息或 harness.started，没有未结束的工具调用 |
| 工具：读 / 搜 / 改 / 跑 / 访问 / 检索 / 派给 / 调用 | 有 `phase: 'start'` 且未结束的工具调用；动词按 docs/design/25 §1 的表 |
| 压缩上下文 | 最近一条是 context.compacted，且之后没有新消息 |
| 等工具 | 只报结束、不报开始的 harness：最近一条是工具调用且 ≥ 15 秒没有新事件 |
| 长步骤 | 以上任一状态持续 ≥ 15 秒（界面按 since 现场计算） |

- 协议：`harness.tool_call` 加 `phase / callId / durationMs`；不报开始的 harness 保持现状（只有结束一拍）。`GraphNode.activity` 由 server 从最近事件推导，web 只负责显示与计时。
- 界面：运行中节点副标题换成动作行（`读取 …/csv.ts`、`运行 npm test`），Agent 形象跟着变（读：眼睛左右扫；改：低头；跑：专注；长步骤：头顶 `…`；压缩：眯眼）。

## 2 时间泳道与上下文曲线

- `GET /api/runs/:runId/timeline` → `RunTimeline`：
  - 每个节点一条泳道，段落：`run`（执行中）、`wait`（等人）、`queue`（就绪未调度）、`tool`（工具步骤，长步骤标 long）、`compact`（压缩）；
  - Agent 节点的段落按调用（invocation）分组，fallback 换 harness 时能看见；
  - 上下文点：每轮 `harness.usage` 的输入 token（含缓存），窗口上限来自 `harness.started.contextWindow`，压缩点来自 `context.compacted`。
- 界面：运行页工具栏"画布 / 时间"切换；时间视图按阶段分组、拖拽框选缩放、滚轮横向平移、双击复位；悬停段落看动作行与耗时；点段落打开节点抽屉并定位到那一步。上下文曲线贴在泳道下方，与时间轴对齐，超过窗口 80% 的区间染琥珀。

## 3 等人限时与交还

- 配置：`HumanNodeDef.timebox` 或空间默认 `TaktConfig.human`：`{ remindAfter?, handbackAfter? }`（`30m` / `2h` / `1d`）。
- 提醒：到 `remindAfter` 记 `human.reminded`（对象：派给的成员；再到一次加上 owner），界面与系统通知各一次，不重复轰炸。
- 交还：只对 `form: 'answer'` 且请求带 `assumption`（提问方给的默认假设）的事项生效。到 `handbackAfter` 时系统以假设作答（answeredBy 为 system，`handedBack: true`），记 `human.handed_back`，下游 prompt 里写明"未获回答，按假设：…"，同时生成一条 kind `assumption` 的待办"按假设推进，待确认"；人之后确认或改答，改答会让依赖它的节点过期。
- 审批（approve）与选择（choice）只提醒，永不自动作答。
- 执行：serve 每分钟检查一次待办的时限（单进程内串行，幂等：以 requestId + 动作做键）；`takt attention tick` 给没有 serve 的场景用。

## 4 转达回执与跳数上限

- `DelegationStatus`：`sent`（已发出）→ `taken`（Lead 回合已接手）→ `started`（派出的任务已开始运行）→ `done` / `replied`；或 `refused`（Lead 拒绝或超过跳数）、`expired`（超过 30 分钟无人接手）、`uncertain`（发送过程中出错、可能已送达）。`uncertain` 不自动重发，界面给"重发"按钮由人决定。
- 管家的 `StewardDelegation.status` 扩展为上面这组；群聊任务卡（RoomMessage kind=task）带 `receipt`。
- 跳数：人发起的消息为 0 跳；Lead 因任务运行的产出 / 消息再派任务，跳数 +1；`RunState.origin.hops` 与 `chain`（上游 taskRunId 列表）。超过 `TaktConfig.lead.maxHops`（默认 10）时拒绝派发，群里发一条系统消息说明链路。

## 5 节点改动卡与回退

- `NodeChanges`：节点在本次执行中改动的文件。
  - 仓库：worktree 相对节点开始前提交（`base`）的 diff，逐文件 `+A −D`、状态（新增 / 修改 / 删除 / 改名）；
  - 存放区：本节点写出的产物版本（`from → to`）。
  - 引擎在节点开始时记录回退点（`node.started` 加 `rewindPoint`：worktree HEAD 与将写产物的当前版本）。
- 卡片：节点抽屉"改动"与运行页节点结束时的事件条都显示；默认 3 行，展开全部；"看 diff"打开统一 diff；没有回退点时按钮置灰并写明原因（而不是隐藏）。
- 回退：`POST …/rewind/preview` → `RewindPreview`（要恢复的文件、会过期的下游节点、阻止原因：运行中 / 下游已在运行 / 工作树有未提交的外部改动）；`POST …/rewind`（带预览给的 token 与 reason）执行：
  - 仓库文件恢复到回退点（只动本节点改过的路径）；
  - 存放区产物写一个新版本，内容为回退点版本（不删历史版本）；本节点新建、回退点里没有前一版本的产物不删也不写，保留原样随生产节点一起标过期，重跑时覆盖（存放区不引入删除 / 墓碑）；
  - 本节点与依赖它的下游标 stale，记 `node.rewound`；预览之后状态变了（token 不符）返回 409。

## 不做 / 推后

- 屏幕边缘悬浮 HUD、桌面宠物式形象：不在网页控制台范围内。
- 跨运行的整段回退（把需求退回到某次运行之前）：后续再做。
- 自动替人审批：不做。
