# 30 打磨：统一形象与组件规范、会话管理、角色配置与自动化

> 状态：已实现（2026-11-10），14 条反馈逐条见 §7。起因：试用一轮后的 14 条反馈，归成三组：页面风格不统一、看着廉价（同一页面几种图标与空态风格并存，管家还是"✦"，Agent 全是同一个机器人图标）；Solo 会话不好管（不能重命名 / 置顶 / 归档 / 删除，看不出状态，没有分组，进展刷屏）；配置不够（管家不能换 harness 和模型，角色的 harness / 模型 / 技能只能改源码，没有定时和自动化，没法往 IM 推进展）。

## 结论

1. **身份只有一套画法：人是按 id 生成的渐变头像，管家、Lead 和每个 Agent 都是节拍蜂。** 蜂按角色拿道具（docs/design/27 §1 早就定了，之前没接上）、按角色着色（六个色相各分本色和深色两档，内置角色各占一档，同一个角色全站同色；harness 只写在文字里，时间线的调用条仍按 harness 着色）；管家拿小铃铛，Lead 拿指挥棒，都是蜂蜜色。Workflow 编辑画布、运行图上的节点和左侧节点库用同一套类型图标（节点在干什么看第二行的动作和右边的状态）；角色蜂用在以「谁」为主的地方：群聊成员、角色列表、节点抽屉标题、Solo 实体卡片。"✦"、机器人图标、深色方块里的星号不再表示任何身份。
2. **组件库就是 `components/ui/`，不引 Tailwind。** 现有 token + CSS 变量 + 原语这套已经覆盖了大部分页面，迁到 Tailwind 要重写几百个文件，收益是写法统一，而这个用"只许用原语 + 审计脚本拦"一样能做到。补齐缺的原语（头像、空态、悬停卡、徽标），加一个 `/ui` 组件陈列页，规则写进 DESIGN.md 的"组件清单"，`ux:audit` 拦违规写法。以后谁来开发（人或 agent），先看陈列页和清单，审计不过 CI 就红。
3. **Solo 会话像邮件一样能管：** 重命名、置顶、归档、删除；悬停看所在空间 / 需求、用的 harness 与模型、更新时间；行尾显示状态（回复中、待你决定、出错）；可按时间、空间、需求、状态分组。进展只保留每个需求最新的一条。
4. **管家对话能随时换 harness 和模型。** 输入框旁一个选择器，列出"能搭配的 harness × 模型"，选了只对这个会话生效；空间设置里仍有默认值。
5. **角色定义 = harness + 模型 + 技能 + 能读的知识库 + 写权限，都能在界面上改。** 写回 `agents/*.md` 的 frontmatter，不用手改源码。代码仓库、知识库、技能是空间共享的，角色只勾选用哪些。优先级：节点 > 角色 > 空间默认；界面上标出生效值来自哪一层。
6. **自动化 = 触发 + 动作 + 通知渠道。** 触发有定时（cron）和事件（需求新建、运行结束 / 失败、等人超时）；动作有启动 workflow、让管家写汇报、发通知；渠道先做飞书 / Lark 机器人、Slack、通用 Webhook，密钥只写环境变量名。典型用法：每天 18:00 把各需求进展推到群里；运行失败立即推给负责人。

## 1 视觉统一（反馈 6、9–14）

| 问题 | 改法 |
|---|---|
| 蜂全是一个样 | `AgentMark` 增加 `role`，按角色给道具；harness 着色挪到身体色上并提高辨识度（同屏最多 6 种色）。运行页节点、节点抽屉标题、角色列表、群聊成员、Workflow 编辑器的 Agent 节点都用它 |
| 管家是"✦"、Lead 是黑底星号 | 新组件 `StewardMark` / `LeadMark`（铃铛蜂 / 指挥棒蜂）；"让管家帮我…"按钮用 14px 铃铛蜂线稿图标，替换 24 处 `Sparkles` |
| 机器人图标、黑底方块 | 删掉；节点抽屉标题、Workflow 节点面板的"Agent"类型都换成角色蜂 |
| 成员头像是淡粉圆 + 字母 | 新组件 `Avatar`：人 = 首字母 + 按 id 稳定取色的实色圆，大小 16 / 20 / 24 / 32 四档；群聊、成员管理、负责人选择统一用它 |
| 空态有两种（灰框小图标 / 大蜂） | `EmptyState` 只保留"睡着的蜂 + 一句话 + 一个主按钮"；小尺寸（卡片内）用 48px 蜂，不再用灰框图标 |
| 空态下方的节拍尺、顶栏下的刻度线 | 节拍尺只出现在加载中；顶栏刻度线改成一条 1px 分隔线，滚动时才出现 |
| 侧栏图标悬停没反馈 | 导航图标悬停做一次 300ms 的小动作（各自不同：总览方块错位、需求列表下移、待办收件箱弹一下……），reduced-motion 下不动 |
| DAG 边动画快且闪 | 传送带改用固定周期（两拍一格）、只改 `stroke-dashoffset`；修重复挂载导致的重播（每次轮询重建 path 元素）；描线只在首次进入时播 |
| 全站风格漂移 | `/ui` 陈列页 + DESIGN.md 组件清单 + `ux:audit` 新规则：禁止用 lucide 的 `Bot` / `Sparkles` 表示身份、禁止页面里自写空态、禁止新写裸色值 |

## 2 Solo 会话（反馈 1、3、4、5、8）

- **操作**：行尾悬停出现"⋯"，菜单里重命名 / 置顶 / 归档 / 删除；置顶的排最上面并带钉子；归档的进"已归档"折叠组；删除要二次确认。
- **悬停卡**（停 400ms 出现）：标题、所在空间 / 需求（可点）、harness · 模型、消息数、最近更新时间、待决定的提案数。
- **状态徽标**：回复中（蜂在动）、待你决定（提案数）、出错（上次回复失败，可重试）、已中断。
- **分组**：右上角筛选菜单，按最近对话时间（默认） / 按空间 / 按需求 / 按状态；选择存在本机。
- **进展去重**：汇报（digest）里同一个需求只留最新一条，后面写"另有 N 条"，点开看全部。
- **换 harness 与模型**：`StewardThread` 记 `harness` / `model`；输入框左下角是选择器，只列能搭配的组合（harness 支持的 provider 协议 ∩ 已配置的模型）。

## 3 角色与共享资源（反馈 2）

- 空间设置 → 角色：从"编辑 Markdown"改成表单（harness、模型、effort、降级链、技能多选、知识库多选、写权限），右侧仍能切到源码。保存写回 frontmatter，留修订原因。
- 共享资源一页看全：代码仓库、知识库、技能是空间级的，表格列出每个角色用了哪些。
- 优先级明确为 节点 > 角色 > 空间默认（`config.roles` 只是没写 harness 的角色的默认值），设置页"模型与 Harness"里的角色路由改名"默认路由"，并在每行标出被哪些角色文件覆盖。

## 4 自动化与 IM（反馈 7）

- 配置：`takt.config.json` 新增 `automations[]`（`{ id, title, enabled, trigger, action, notify? }`）与 `channels[]`（`{ id, kind: 'feishu' | 'slack' | 'webhook', urlEnv, secretEnv? }`）。
- 触发：`{ schedule: '0 18 * * 1-5' }`（本机时区）或 `{ event: 'run.finished' | 'run.failed' | 'requirement.created' | 'attention.overdue', filter? }`。
- 动作：`start_workflow`（对需求跑某个 workflow）、`digest`（管家按模板写汇报）、`notify`（只发消息）。
- 每次执行留一条记录（触发时间、动作、结果、发送回执），在"自动化"页能看到最近 20 次，失败可重试。
- 界面：空间侧栏加"自动化"，空态给 4 个模板（每日进展、运行失败告警、等人超时提醒、新需求自动启动）。

## 6 不做

- 不迁 Tailwind（理由见结论 2）。
- IM 先只做单向推送，不做从群里回指令（那是群聊 Lead 的事，后面再接）。
- 不做会话文件夹 / 标签，分组用现成的空间和需求。
