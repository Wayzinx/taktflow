# 07 · 上下文管理与可视化

## 解决什么问题

长任务失败的头号原因是上下文：读了太多无关内容、该读的没读、压缩后目标和约束丢了。现在这些都发生在 harness 内部，人看不到，只能事后猜。

## 原则

1. **拆**：一个节点只做一件事，只吃声明的输入，每个节点默认新会话（`session: 'fresh'`）。
2. **落盘**：每一步的结论写成产物，下一步读文件，不靠会话记忆；压缩后续跑只认文件。
3. **隔离**：大量检索交给知识层或子节点，主节点只拿结论。

## 上下文账本

引擎在每个 agent 节点开始前组装上下文，记一条 `context.assembled`（`ContextSnapshot`）：

| 来源（ContextSource） | 例子 | token |
|---|---|---|
| role | 角色说明 `.takt/agents/dev.md` | 估算 |
| skill | 技能文件 | 估算 |
| artifact | `spec/spec.md@v3`、`design/api-contract.json@v2` | 估算 |
| knowledge | 知识检索命中（路径 + 摘要） | 估算 |
| prompt | 节点 prompt | 估算 |
| history | 续聊时带入的历史 | harness 报告 |
| tool_result | 运行中读的文件、命令输出 | harness 事件 |

- 声明的输入按顺序内联，最多占预算的一半，放不下的只给路径（agent 按需自己读），记 `included: false` 和原因；
- 运行中 harness 报告的工具调用（读了哪些文件）补进账本，可以对比"**计划读的**"和"**实际读的**"；
- harness 报告压缩时记 `context.compacted`（`CompactionRecord`：压缩前后 token、摘要、丢了什么）。

token 估算：中日韩字符及全角标点每个计 1 token，其余字符数除以 4 向上取整；harness 能报真实用量时以真实值为准。

## 可视化（Web 节点抽屉的"上下文"Tab）

- **堆叠条**：按来源分色，显示占预算的比例，超预算标红。
- **清单**：每一项的来源、标题、引用、token、是否注入，点开看内容。
- **压缩时间线**：每次压缩前后 token 对比、摘要、丢弃项。
- **计划 vs 实际**：声明的输入里哪些没读，运行中额外读了哪些。

## 策略（后续）

- 预算策略：超预算时按优先级裁剪（prompt > spec > 契约 > 知识 > 历史），裁剪写进账本。
- 压缩前钩子：压缩前把目标、约束、待办写回存放区（`decisions/` 或节点的 journal），压缩后自动注入。
- 跨节点：同一角色的连续节点可以选择续聊（`session: 'resume'`），账本会显示继承了多少历史。

## MVP 范围

- 组装时的账本（静态部分）+ mock / codex / claude-code 适配器能报的用量与工具调用；
- Web 堆叠条 + 清单 + 压缩记录列表；
- 预算策略只做标红，不做自动裁剪。
