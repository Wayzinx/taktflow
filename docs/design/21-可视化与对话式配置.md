# 21 · 可视化与对话式配置：不让用户改源文件

## 解决什么问题

在 DeepSeek Harness（dsh）里实际使用面板，问题集中在三类：

1. **布局**：面板在 App 常见宽度（主区 900–1100px）下挤在一起。需求表的“需求”列被固定宽度挤成 0（标题消失、表头重叠），总览五张指标卡在四列网格里剩一张单独换行，运行页画布初始视野没对准节点。
2. **改不了**：Workflow 只能看和画布编辑，不能新建、复制、改名、删除、设默认；角色、技能只能改 markdown + YAML 源文件，不能新建、删除；知识源、自主程度、环境部署、自测命令、默认流程只能手改 `takt.config.json`；空页面全是 `takt skill add`、`takt init` 这类命令行提示。
3. **不该出现的配置**：在 dsh 里所有角色都由 dsh 原生子 Agent 执行、用 App 的模型，“模型与 Harness”页列出的 12 个 harness 和模型表没有意义；角色卡片还显示 `claude-code` / `codex`，与实际执行不符。“成员 / 职责”是多人协作概念，dsh 本机只有一个用户。

另有两个插件侧的硬伤：插件同一时间只支持一个空间（第二个目录 init 报 `TAKT_SPACE_ROOT_MISMATCH`）；早期版本建的空间引用了不存在的 workflow 文件，没有升级路径。

## 原则

- **页面上能看到的配置都能在页面上改**，用表单，不用源文件；源文件编辑保留为“高级 · 查看源文件”。
- **也能用一句话让 Lead 改**：每个设置页顶部有“告诉 Lead 你想怎么改”的输入框，Lead 用受控工具改，改动与人在页面上改走同一套校验和修订记录。
- **所有修改可追溯、可撤回**：每次写入记作者（人 / agent + onBehalfOf）、原因、前后内容，可在“修改记录”里恢复到任一版本。
- **宿主决定能力**：数据源声明宿主能力（`host`），dsh 下隐藏 harness / 模型 / 成员管理；独立 Web 保持原样。

## 宿主能力（web）

`DataSource.host?: HostCapabilities`：

```ts
interface HostCapabilities {
  kind: 'standalone' | 'dsh'
  /** 是否在面板里管理 harness 与模型；dsh 为 false（用 App 的） */
  manageRuntime: boolean
  /** 是否管理成员与职责；dsh 为 false */
  manageMembers: boolean
  /** 角色可选的模型；不提供时角色表单只显示“跟随 App” */
  models?: () => Promise<Array<{ id: string; label: string }>>
  /** 把一句话交给当前空间绑定的 Lead；返回会话 id（便于打开） */
  askLead?: (text: string, context?: { page: string; target?: string }) => Promise<{ sessionId: string }>
  openSession?: (sessionId: string) => void
}
```

## 设置页信息架构（dsh 下）

| 页签 | 内容 |
| --- | --- |
| 运行策略 | 默认流程、自主程度（全 AI / 关键节点人审 / 全部人审，带说明）、环境部署（setup / deploy / healthcheck / teardown / env，带“测试一下”按钮可选）、自测命令（testCommand、超时）、预算 |
| 角色 | 列表 + 表单：名称、说明、职责说明（markdown 编辑 + 预览）、技能（从空间技能多选）、可读范围 / 可写范围（路径标签 + 常用预设：产品代码、需求产物、测试、全部只读）、模型（跟随 App / 宿主提供的模型）、被哪些流程节点使用；新建（空白或复制现有角色）、删除（被流程引用时拒绝并列出引用） |
| 技能 | 列表 + 表单：名称、何时使用（description）、正文；新建、删除、被哪些角色使用 |
| 知识源 | 列表 + 按类型的表单（grep：目录与忽略；wiki / git-history：目录；workspace；codegraph / database / api-registry 无参数）、新增、删除 |
| 代码仓库 | 保持现有 |
| 经验 | 保持现有 |
| 成员、模型与 Harness | 仅 `manageMembers` / `manageRuntime` 为 true 时显示 |

角色的 `harness` 字段在 dsh 下不显示、不编辑；保存时原样保留。

## Workflow 列表

- 新建：从模板（标准交付流水线、轻量改动、精简 SDLC、空白）或复制现有流程；填标题与 id。
- 每行操作：打开、复制、改名、设为默认、删除（二次确认；唯一流程不能删；历史运行有快照不受影响）。
- 默认流程有标记；模板标题去掉“作者版”等内部叫法，`taktflow-standard` 叫“标准交付流水线（完整）”、`sdlc` 叫“精简 SDLC”、`quick-fix` 叫“轻量改动”。
- 画布编辑保持；画布区域在窄屏下优先给画布空间（节点面板与属性面板可折叠）。

## 服务端写操作（api-core）

全部走租约、要求 `reason`、写审计；人 actor 为面板用户，agent actor 带 `onBehalfOf`。

| op | params | body | 说明 |
| --- | --- | --- | --- |
| `space.settings` (读) | – | – | 结构化设置：`config` 子集（autonomy、defaultWorkflow、environment、selftest、budget、knowledge）、角色（解析后的 frontmatter + instructions + usedBy）、技能（name、description、body、usedBy）、知识源类型表（kind、选项 schema、说明）、模板列表 |
| `space.config.update` | – | `{ patch, reason }` | 只允许上述白名单字段；整体校验通过才落盘；保留未知字段与格式（2 空格 JSON） |
| `space.agent.save` | `{ role }` | `{ profile: Partial<AgentProfile>, instructions?, create?: boolean, baseHash?, reason }` | 结构化保存角色；保留未出现在表单里的 frontmatter 字段；`baseHash` 不一致返回 409 |
| `space.agent.delete` | `{ role }` | `{ reason }` | 被任何 workflow 节点引用时 409，返回引用列表 |
| `space.skill.save` | `{ name }` | `{ description, body, create?: boolean, baseHash?, reason }` | 写 `skills/<name>/SKILL.md` |
| `space.skill.delete` | `{ name }` | `{ reason }` | 被角色引用时 409 |
| `space.file.revisions` (读) | `{ kind, name }` | – | 角色 / 技能 / 配置文件的修订列表（作者、原因、时间、hash） |
| `space.file.rollback` | `{ kind, name, rev }` | `{ reason }` | 恢复到某个修订（本身记一个新修订） |
| `workflow.create` | – | `{ id, title, from: { template } \| { workflow }, reason }` | 新文件 + 注册到 `workflows`；id 冲突 409 |
| `workflow.meta` | `{ id }` | `{ title?, default?: true, reason }` | 改标题走源码编辑（留修订）；设默认写 `route.defaultWorkflow` |
| `workflow.delete` | `{ id }` | `{ reason }` | 取消注册并删除文件（含 hooks / layout 旁路文件仅当没有其它流程引用）；有运行中的运行时 409 |
| `space.upgrade` | – | `{ dryRun?: boolean, reason }` | 旧布局空间升级：补齐缺失模板、去掉不存在的 workflow 引用、注册标准流程；不改已有角色和需求数据；dryRun 返回变更清单 |

修订存储：复用 workflow 修订的对象存储思路，`kind ∈ agent | skill | config`，每次写入保存快照与元数据。

## 对话式配置（插件）

- Lead 新增工具 `takt_config`（第 7 个工具）：`show`（读结构化设置）、`set_config`、`save_role`、`delete_role`、`save_skill`、`delete_skill`、`workflow_create`、`workflow_meta`、`workflow_delete`、`workflow_edit`（改 workflow 源码，复用 `workflow.source.replace` 的校验）、`upgrade`、`rollback`。全部调用上面的 api-core 操作，actor 为 agent、`onBehalfOf` 为绑定的人、`reason` 必填。
- 只在用户明确要求改配置时使用；改完回复“改了什么、为什么、怎么撤回”。删除类操作先用 `takt_ask_human` 确认。
- 面板“告诉 Lead”：`POST /api/taktflow.op` `{ p: 'lead.ask', text, page, target }` → 宿主把这句话作为用户消息投递到该空间绑定的 Lead 会话（没有绑定会话时新建一个 taktflow 会话），返回 `sessionId`，面板随即打开会话。

## 多空间（插件）

- 空间注册表支持多个根；面板全局入口在多于一个空间时显示空间切换器，会话标签页固定显示该会话的空间。
- 旧布局检测：配置引用的 workflow 文件不存在、或 agents 在 `.takt/agents` → 面板顶部提示“这个空间由旧版本创建”，一键（或让 Lead）`space.upgrade`。

## 布局修复

- 表格：标题列 `min-width`，低优先级列（负责人、当前节点、成本、更新）按容器宽度隐藏（container query），不再出现 0 宽列；ID 列不折行。
- 指标卡：`repeat(auto-fit, minmax(180px, 1fr))`。
- 页面宽度统一：内容最大宽度一致（总览、列表、设置、Workflow），不再一部分全宽、一部分窄居中；空间名不用等宽字体。
- 运行页画布首次进入自动适配全部节点。
- 文案：去掉 `.takt/workspaces/<REQ>/` 之类实现细节和命令行提示，空状态给按钮。

## 验收

在 dsh web 隔离环境（`--profile web`）主区宽度 1000px 与 1440px 各截一遍：总览、需求、需求详情、运行、Workflow 列表与编辑、设置各页签；表单新建 / 修改 / 删除角色、技能、知识源、流程，改运行策略；在面板里说一句“把评审最多轮次改成 2”，Lead 完成修改且修订可恢复。
