## 一、运行页

1. **运行中细分**（`GraphNode.activity`）：
   - 节点副标题换成动作行，动词沿用 `lib/actions` 的动词表，例如"读取 …/csv.ts""运行 npm test"；没有动作时显示"思考中"。
   - 计时由 web 根据 `since` 现场计算，超过 15 秒加"长步骤"标记，并显示已用秒数。
   - AgentMark 随状态变化：
     | 状态 | 形象 |
     |---|---|
     | 读 / 搜 | 眼睛左右扫 |
     | 改 | 低头 |
     | 跑 | 专注 |
     | 压缩 | 眯眼 |
     | 等工具 | 眼睛半闭 |
     | 长步骤 | 头顶出现 `…` |
   - 全部动效放在 no-preference 里；reduced-motion 下只换静态表情。
2. **时间视图**：工具栏加"画布 / 时间"切换（Segmented），写入 URL query `view=time`。
   - 泳道：
     - 按阶段分组，节点一行；Agent 节点可以展开成按调用分组的子行，标出 fallback。
     - 段落颜色：run 用运行色，wait 用等待色，queue 用浅灰条纹，tool 用细段（长步骤加深），compact 用菱形标记。
     - 进行中的段右端跟着当前时间增长（每拍刷新一次）。
   - 操作：拖拽框选缩放，滚轮横向平移，双击复位。悬停段落显示动作行与耗时；点击打开节点抽屉，并定位到"过程"里的那一步。
   - 上下文曲线：放在泳道下方，与泳道共用时间轴。
     - 每个节点一条细线；超过窗口 80% 的区间染琥珀；
     - 窗口上限画虚线，压缩点用竖线标记；
     - 没有窗口上限时只画曲线，并注明"窗口未知"。
   - 实现：纯 SVG，不引新依赖。条形用 clip-path 从左打开（与 docs/design/25 一致）。
3. **节点结束事件条与改动卡**：
   - 节点完成时，事件条显示"改了 N 个文件 +A −D"，点开就是改动卡。
   - 改动卡（`NodeChanges`）：仓库与存放区分组，默认显示 3 行，可展开全部；"看 diff"打开统一 diff，复用 `review/line-diff`。
   - 没有回退点时，"退回到这个节点之前"按钮置灰，并写明原因。
4. **回退预览对话框**：
   - 内容：要恢复的文件、会过期的下游节点（列表 + 在画布上高亮）、阻止原因、必填的原因输入。
   - 确认后带上 token 执行。如果返回 409，提示"状态变了，已重新预览"，并自动重新预览。
   - 成功后弹 toast，并把画布上过期节点标出来。

## 二、节点抽屉

1. **检查点 tab**（有 `checkpoints` 时出现）：
   - 列表：每个检查点一行，内容为角色、对象、状态（done / error / skipped）、耗时。
   - 展开后：
     - **快照**：文件清单（角色 target / reference，版本，来源）和只读方式（sandbox / permissions / none，none 显示警告）；点文件看快照内容。
     - **调用身份三层**：模型 / effort 各一行"请求 → 解析 → 回报 → 是否生效"，不确定的显示"未知"，不拿请求值冒充；技能列声明、已提供的哈希、确认状态。
     - **职责清单**：逐条 ok / issue / na，issue 链到对应问题键。
   - 门禁检查项显示 pass / fail / error 三态，error 用"检查出错"文案和独立样式，不和 fail 混在一起。
2. **评审 tab**：
   - 问题显示 `ISS-n` 键。
   - 状态分开显示：`claimed_fixed`（作者说修好了，虚线勾）与 `verified_fixed`（评审者确认，实线勾）；`not_checked` 显示"本轮未复查"。
   - 轮次时间线上可以点问题键，看它的历史（提出 → 作者回应 → 复查）。
3. **改动 tab**（有 `changes` 时出现）：完整的改动卡，加回退入口。
4. **概览**：等人节点显示时限（几分钟后提醒、几分钟后按假设交还），交还后显示"已按假设推进：…"。

## 三、需求页与待办

1. **缺陷 tab 重做**：分成观察与缺陷两层。
   - **观察列表**：来源、类型、时间、所属检查点；可以多选后"创建缺陷"。
   - **缺陷详情**：
     - 有效性与处理状态分开显示；
     - 关联的观察；
     - 合并建议卡（接受 / 拒绝 / 撤销）。
   - **归因卡**：每个相关检查点一行，五个条件逐项显示：
     - 每项状态为"成立 / 不成立 / 无法判断"，并附依据；
     - 结论为 should_have_caught / material_missing / not_executed / out_of_scope / undetermined；
     - 改判时弹原因输入，人工结论带"人工"标记。
   - 编辑时冲突（baseRevision 不符）提示"别人刚改过"，并给"载入最新"。
2. **待办**：
   - 待办卡显示时限进度：一条细进度条，接近交还时限变琥珀。
   - 新增 kind `assumption`（"待确认假设"，图标 Lightbulb）：显示原问题、系统按的假设、交还时间；两个动作为"确认假设"和"改答"，改答时说明会让哪些节点过期。

## 四、评测页

1. **报告**：
   - 每个变体显示通过率和 Wilson 95% 区间（区间条加点估计）、误报、证据不足；
   - 样本太少时整块加"探索性"标记；
   - 门槛结论（通过 / 不通过 / 证据不足）旁附门槛快照。
2. **运行状态 refused**：显示拒绝原因（隔离条件哪条不满足），并给出下一步怎么做。
3. **隔离信息**：运行详情显示隔离方式（sandbox / readOnly / simulated）和候选包 id。
4. **样本**：用例列表区分 must_catch / clean，可以退役（需填原因）。

## 五、设置页

**质量日志**放在运行时 tab 或单独一个 tab：
- 显示链是否完整、锚点、各运行的入账游标、上次同步时间、M3 是否已导入；
- 链完整、锚点落后时显示"修复锚点"（需填原因）；
- 链被篡改时显示红色警告和说明，不提供修复按钮。

## 六、群聊与管家

1. **群聊任务卡**：
   - 显示 `receipt`：已发出 → 已接手 → 已开始 → 完成，做成一排小站点，复用 StageRail 的 sm 视觉语言但更轻；
   - refused 时显示原因与跳数链路；
   - expired / uncertain 时给"重发"按钮，由人决定，需二次确认。
2. **管家转达卡**：同样的回执状态；uncertain 时写明"可能已送达，重发前请先看群聊"。

## 七、mock

- `api/mock-m5.ts`：
  - 一个运行中的 Agent 节点，activity 每 4 秒轮换一次状态，其中一次超过 15 秒；
  - 一个带 fallback 的时间线和上下文曲线（含压缩点、超过 80% 的区间）；
  - 一个可回退节点（仓库 3 个文件、存放区 1 个产物）、一个阻止回退的节点；
  - 检查点：3 个评审者，其中一个 skipped；快照的 readOnly 方式一个为 none；三层取值含"未知"；
  - 问题台账：ISS-1 状态为 claimed_fixed，ISS-2 为 verified_fixed，ISS-3 为 not_checked；
  - 门禁 error。
- `api/mock-defects.ts` 扩展：观察、两个缺陷、合并建议，以及五个条件结论各一例（含 undetermined）。
- `api/mock-eval-runs.ts` 扩展：一份 Wilson 报告、一次 refused 的运行、一个探索性报告。
- 待办：一条接近交还时限的 answer、一条已交还的 assumption 待办、一条 approve（只提醒）。
- 群聊：一张 refused 的任务卡（跳数超限）、一张 uncertain 的转达。
